# Synthetic Bug-Injection Mutants

Alongside historical upstream `libsignal` commits (`cheval26-*` in [`../README.md`](../README.md)), this directory maintains **17 synthetic regression mutants** (`kind = "synthetic"` in [`third_party/libsignal/bug-injection/synthetic/bugs.toml`](../../../third_party/libsignal/bug-injection/synthetic/bugs.toml)). Each mutant is a small forward Rust patch against `libsignal v0.105.4` (and/or `libsignal-session`'s CLI wrapper via `cli_patch` or `patch_target = "libsignal-session"`) that introduces a realistic protocol, state-persistence, key-erasure, or process-boundary bug—such as leaking a MAC key in an unencrypted header, forgetting to wipe rotated-out private keys or consumed one-time pre-keys from disk, skipping ciphertext MAC verification, omitting handshake secrets, accepting replayed ciphertexts, or writing secrets to stdout before aborting—used to test that our top-level `libsignal-cli` symbolic security specification (`SignalSessionSecure` / `CompRefinesCliBinary`; committed disproof obligations currently target the retired untrusted placed helper `SignalSessionSecurePlaced`, pending retarget) actually catches real implementation bugs.

---

## What Each File Means

Every synthetic mutant is represented by four committed artifacts in the bug-injection pipeline (driven internally by `scripts/bug_injection.py`, not included in the public export), plus machine-checked specification refutations in `Symbolic/BugInjection/Proofs/Synthetic*/Top.lean`:

- **Patch** (`third_party/libsignal/bug-injection/synthetic/patches/<bug>/v0.105.4.diff`, plus optional `cli.diff` when `cli_patch` is set): The forward Rust diff applied to a clean `libsignal v0.105.4` checkout (or to `third_party/libsignal/libsignal-session/` when `patch_target = "libsignal-session"` or `cli_patch` is set) to introduce the bug. `scripts/bug_injection.py verify-patches` checks all SHA-256 hashes and verifies that every diff applies cleanly.
- **Witness** (`third_party/libsignal/bug-injection/synthetic/witnesses/<witness>.json` → `Symbolic/BugInjection/Synthetic/Witnesses/<Name>.lean`): The concrete attack scenario and its recorded trace. The JSON file specifies the sequence of `libsignal-cli` commands (`init`, `send`, `recv`, `clear`, with optional `"with_opk": true`) and disk compromise events (`leak`) the test harness runs. Running `scripts/bug_injection.py run` executes that scenario on both the patched Rust binary and unmodified `libsignal v0.105.4`, checks that their observable traces differ (`live`), and records the mutant's exact `CliEvent` trace into `Synthetic/Witnesses/<Name>.lean`.
- **Non-vacuity** (`Symbolic/BugInjection/Synthetic/NonVacuity/<Name>.lean`): A kernel-checked Lean theorem (`nonvacuous : ∃ i r, fits i r`, compiled automatically in the default `lake build`) proving that the witness's concrete public keys, ciphertexts, and external cryptographic contracts are mutually satisfiable. This guarantees that a specification disproof genuinely rejects the buggy trace rather than succeeding vacuously from contradictory setup assumptions.
- **Disproof** (`Symbolic/BugInjection/Synthetic/Disproofs/<Name>.lean`): The per-mutant Lean refutation obligation, elaborated when `scripts/bug_injection.py disproof` re-extracts the patched ARM64 machine code and links the mutant's `libsignal-cli` ELF (`CV_BUG_INJECTION=<bug>`). Each module currently states `theorem disproof : ¬ DY.Libsignal.Composed.Security.SignalSessionSecurePlaced mutantCliElfBytes`—the negation of the retired untrusted placed helper (`Symbolic/Proofs/SpecLemmas/SecurityBinaryPlaced.lean`, pending retarget to the ELF-direct headline `SignalSessionSecure` in `Symbolic/Specifications/Security/Binary.lean`)—designed to be discharged via `not_signalSessionSecurePlaced_of_witness` ([`Witnesses/CliShapePlaced.lean`](../Witnesses/CliShapePlaced.lean)) from a machine-free **spec half `(S)`** (proved in `Symbolic/BugInjection/Proofs/Synthetic*/Top.lean` for **16/17** mutants below; only `synthetic-pre-abort-stdout-exfil` remains open) and an **implementation half `(I)`** (showing the patched ARM64 ELF produces that trace).

## Plain-Language Descriptions of the Mutants

### 1. `synthetic-addr-key-leak` — Leaking the MAC Key in Wire Metadata

On initial unacknowledged `0x03` `PreKeySignalMessage` sends, `libsignal v0.105.4` populates `SignalMessage` protobuf field 6 (`addresses`) with the 36-byte serialized sender and recipient `ProtocolAddress` UUID pair (while `0x02` whisper messages omit field 6). This mutant replaces that serialized address pair in `SignalMessage::new` with `Some(mac_key.to_vec())`, broadcasting Alice's raw 32-byte per-message HMAC key in cleartext inside protobuf field 6 on her very first `send`. Any passive network observer can read `mac_key` directly off the wire and forge authenticated messages to Bob. *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticAddrKeyLeak/Top.lean`](../Proofs/SyntheticAddrKeyLeak/Top.lean).)*

### 2. `synthetic-unack-prekey-omitted` — Omitting the Initial `PreKeySignalMessage` Envelope

When Alice initiates a session from Bob's pre-key bundle, she must wrap her encrypted `SignalMessage` inside an outer `0x03` `PreKeySignalMessage` envelope carrying her identity key, ephemeral base key, Kyber-1024 ciphertext, and the IDs of Bob's pre-keys until she decrypts Bob's first reply. This mutant deletes the `set_unacknowledged_pre_key_message` and `set_unacknowledged_kyber_pre_key_id` calls in `process_prekey_bundle`. As a result, Alice's very first `send` emits a bare 106-byte `0x02` whisper `SignalMessage` instead of a 1,797-byte `0x03` `PreKeySignalMessage`, omitting all handshake key material so Bob has no way to establish the session. *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticUnackPrekeyOmitted/Top.lean`](../Proofs/SyntheticUnackPrekeyOmitted/Top.lean).)*

### 3. `synthetic-recv-chain-priv-retained` — Retaining Rotated-Out Ratchet Private Keys on Disk

`libsignal`'s `SessionStructure` protobuf reuses a single `Chain` message schema for both the active `sender_chain` (which stores a 32-byte `sender_ratchet_key_private` in field 2) and the list of up to five `receiver_chains` (which only need the peer's public ratchet key, so honest code sets `sender_ratchet_key_private: vec![]`). During `RatchetState::dh_ratchet_step`, this mutant copies the party's rotated-out `sender_private_key` into `receiver_chains[*].sender_ratchet_key_private` instead of clearing it. Wire traffic looks identical to clean `libsignal`, but up to five generations of rotated-out X25519 private keys remain sitting in the session file on disk—allowing an attacker who compromises the device after multiple DH ratchet steps to recover past private keys and break Post-Compromise Security. *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticRecvChainPrivRetained/Top.lean`](../Proofs/SyntheticRecvChainPrivRetained/Top.lean).)*

### 4. `synthetic-keep-opk` — Failing to Delete a Consumed One-Time Pre-Key

In Signal's PQXDH handshake, Bob's signed pre-key and last-resort Kyber pre-key are medium-term keys rotated periodically, whereas Bob's One-Time Pre-Key (`OPK`) provides immediate forward secrecy for Alice's initial handshake: as soon as Bob decrypts a `PreKeySignalMessage` naming `pre_key_id`, `message_decrypt_prekey` calls `pre_key_store.remove_pre_key(pre_key_id)` to wipe that private key from Bob's disk. This mutant skips `remove_pre_key`, leaving Bob's 32-byte OPK private key intact inside `bob/one-time-pre-keys/` after the handshake completes, allowing Alice to initiate a second session reusing the same one-time pre-key (`exit 0` on the mutant vs. `exit 1` on clean `libsignal v0.105.4`). *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticKeepOpk/Top.lean`](../Proofs/SyntheticKeepOpk/Top.lean).)*

### 5. `synthetic-verify-mac-skip` — Skipping Ciphertext MAC Verification

Every Signal ciphertext ends with an 8-byte truncated HMAC-SHA256 tag computed over the sender and receiver identity public keys, the protocol version byte, and the serialized `SignalMessage` protobuf. This mutant ignores the constant-time `our_mac.ct_eq(their_mac)` comparison in `SignalMessage::verify_mac` and unconditionally returns `Ok(true)`. When an active network attacker overwrites the trailing 8-byte MAC tag on Alice's message with `ffffffffffffffff` (or flips chosen bits in an AES-256-CBC ciphertext), clean `libsignal v0.105.4` immediately exits with an authentication error (`exit 1`), whereas the mutant accepts the forged packet (`exit 0`) and outputs plaintext. *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticVerifyMacSkip/Top.lean`](../Proofs/SyntheticVerifyMacSkip/Top.lean).)*

### 6. `synthetic-promoted-prekey-headers` — Skipping Outer Identity Checks on Session Promotion

Until Alice receives Bob's first reply, every message she sends is wrapped in an outer `0x03` `PreKeySignalMessage` carrying her `identity_key` and ephemeral `base_key`. When Bob receives a second bundled `PreKeySignalMessage` whose `base_key` matches an already-established session, clean `libsignal v0.105.4` still verifies `identity_store.is_trusted_identity(remote_address, their_identity_key, Receiving)` before calling `promote_matching_session` and saving `their_identity_key`. This mutant promotes a matching `base_key` session before the `is_trusted_identity` check. When an active attacker swaps the outer `identity_key` on a bundled `PreKeySignalMessage` with a foreign key, clean `libsignal` rejects (`exit 1`), whereas the mutant accepts (`exit 0`), decrypts the inner whisper ciphertext, and overwrites Bob's pinned identity file for Alice on disk. *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticPromotedPrekeyHeaders/Top.lean`](../Proofs/SyntheticPromotedPrekeyHeaders/Top.lean).)*

### 7. `synthetic-implicit-reject-mac` — Accepting Unauthenticated Handshakes on Kyber Implicit Rejection

CRYSTALS-Kyber-1024 uses the Fujisaki–Okamoto transform with implicit rejection: decapsulating a tampered `kyber_ciphertext` does not return an error, but instead returns a pseudorandom fallback shared secret that causes subsequent inner `SignalMessage` HMAC-SHA256 verification to fail inside `try_decrypt_from_record`. This mutant replaces `try_decrypt_from_record(...)?` in `message_decrypt_prekey` with `.unwrap_or_default()`. When an attacker corrupts `kyber_ciphertext` and zeroes the trailing 8-byte inner `SignalMessage` MAC, clean `libsignal v0.105.4` rejects (`exit 1`) without modifying Bob's state, whereas the mutant exits `0` with empty plaintext and persists the unauthenticated session to disk. *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticImplicitRejectMac/Top.lean`](../Proofs/SyntheticImplicitRejectMac/Top.lean).)*

### 8. `synthetic-evicted-chain-skipped-key` — Accepting Skipped Keys from Evicted Receiver Chains

In `libsignal v0.105.4`, `RatchetState::dh_ratchet_step` maintains a bounded FIFO ring buffer of at most `MAX_RECEIVER_CHAINS = 5` peer ratchet public keys; because skipped message keys live inside each `Chain` entry (`receiver_chains[i].message_keys`), evicting the oldest `Chain` after five subsequent peer DH ratchets simultaneously erases any unconsumed skipped message keys from that epoch. This mutant deletes the `while self.receiver_chains.len() > consts::MAX_RECEIVER_CHAINS` eviction loop in `dh_ratchet_step`. After Alice sends messages 0 (`skip-0`) and 1 (`init-1`) on her initial ratchet key and five subsequent ping-pong DH ratchets advance the session, clean `libsignal v0.105.4` has evicted epoch 0 and rejects a delayed delivery of message 0 (`exit 1`), whereas the mutant retains skipped keys indefinitely and decrypts it (`exit 0`). *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticEvictedChainSkippedKey/Top.lean`](../Proofs/SyntheticEvictedChainSkippedKey/Top.lean).)*

### 9. `synthetic-zero-base-key-pqxdh` — Accepting Zero / Low-Order `base_key` in PQXDH Handshakes

In `libsignal v0.105.4`, `pqxdh_accept` validates `parameters.their_ephemeral_key.is_canonical()` before any Diffie-Hellman computation and propagates `calculate_agreement(...)?` errors whenever `their_ephemeral_key` is a low-order X25519 point whose shared secret is all zeroes. This mutant omits the `is_canonical()` check and replaces `calculate_agreement(&parameters.their_ephemeral_key)?` with `.unwrap_or_else(|_| Box::new([0u8; 32]))`. When an active participant knowing `DH(ikA, spkB)` substitutes `base_key = 0x05 ‖ 0^32` on Alice's initial `PreKeySignalMessage` (preserving her honest Kyber-1024 ciphertext and SPQR `pq_ratchet` header) and re-encrypts/MACs `forged!!!` under `DH2 = DH3 = 0^32`, clean `libsignal v0.105.4` rejects (`exit 1`), whereas the mutant accepts (`exit 0`) and outputs `forged!!!`. *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticZeroBaseKeyPqxdh/Top.lean`](../Proofs/SyntheticZeroBaseKeyPqxdh/Top.lean).)*

### 10. `synthetic-pqxdh-kem-ss-omitted` — Omitting the Kyber Shared Secret in PQXDH Key Derivation

In `pqxdh_initiate` and `pqxdh_accept`, `libsignal v0.105.4` concatenates the 32-byte `0xff` domain prefix, three (or four) 32-byte X25519 agreements, and the 32-byte CRYSTALS-Kyber-1024 shared secret `ss` before deriving the initial root key and SPQR key via `HandshakeKeys::derive(&secrets)`. This mutant still runs Kyber-1024 encapsulation and decapsulation—consuming the same CSPRNG bytes and emitting the 1,568-byte `kyber_ciphertext` on the wire—but omits `secrets.extend_from_slice(ss.as_ref())` on both sides. Consequently, Alice's initial `send` derives symmetric keys from classical DH material alone, and Bob accepts a handshake whose `kyber_ciphertext` was modified in transit (`exit 0`), whereas clean `libsignal v0.105.4` derives a mismatched root key under implicit rejection and rejects (`exit 1`). *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticPqxdhKemSsOmitted/Top.lean`](../Proofs/SyntheticPqxdhKemSsOmitted/Top.lean).)*

### 11. `synthetic-dh-ratchet-no-send-step` — Omitting the Sending Half-Step in `dh_ratchet_step`

In `RatchetState::dh_ratchet_step`, `libsignal v0.105.4` performs both half-steps of a Double Ratchet transition upon receiving a new peer ratchet public key: it first derives `receiver_chain_key` using the current `sender_private_key`, and then generates a fresh ephemeral X25519 keypair `new_sender_key` to advance `root_key` and replace `self.sender_chain`. This mutant omits the sending half-step, leaving `self.sender_chain` bound to the party's previous keypair (for Bob's first reply, his static signed pre-key). Bob's `send` therefore emits a `0x02` whisper message carrying his unrotated signed pre-key public key in `sender_ratchet_key` instead of a fresh ephemeral ratchet key. *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticDhRatchetNoSendStep/Top.lean`](../Proofs/SyntheticDhRatchetNoSendStep/Top.lean).)*

### 12. `synthetic-decrypt-clone-not-persisted` — Omitting Post-Decrypt Session State Persistence

Inside `try_decrypt_from_record`, `libsignal v0.105.4` clones `current_state` before running `try_decrypt_with_state` so failed decryption trials do not mutate the session record, and then writes the advanced state back via `record.set_session_state(current_state)` upon success. This mutant removes that `record.set_session_state(current_state)` call. On an initial `PreKeySignalMessage`, Bob creates a fresh session record (`index = 0`), decrypts counter `0` on the cloned state (`index = 1`), and persists the pre-decrypt record (`index = 0`) to disk; when the same `PreKeySignalMessage` is replayed, clean `libsignal v0.105.4` rejects it as a duplicate message (`exit 1`), whereas the mutant accepts the replay (`exit 0`) and outputs plaintext a second time. *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticDecryptCloneNotPersisted/Top.lean`](../Proofs/SyntheticDecryptCloneNotPersisted/Top.lean).)*

### 13. `synthetic-signal-msg-canonical-mac` — Canonicalizing `SignalMessage` Bytes Prior to MAC Verification

In `SignalMessage::try_from`, `libsignal v0.105.4` stores the exact incoming wire slice `Box::from(value)` in `SignalMessage.serialized` so `verify_mac` authenticates the raw wire encoding rather than only the decoded protobuf fields. This mutant re-encodes the decoded `proto::wire::SignalMessage` together with a reconstructed `0x44` version byte into a canonical buffer and stores that buffer in `serialized`. When a non-canonical wire encoding of Bob's whisper message is delivered (with low version nibble `0x4f`, a shadowed earlier `counter` field, and an unknown protobuf tag) carrying Bob's unmodified 8-byte MAC tag, clean `libsignal v0.105.4` rejects on MAC mismatch (`exit 1`), whereas the mutant canonicalizes away the wire modifications before `verify_mac` and accepts (`exit 0`). *(Caught in `Symbolic` with machine-checked `(S)` in [`Proofs/SyntheticSignalMsgCanonicalMac/Top.lean`](../Proofs/SyntheticSignalMsgCanonicalMac/Top.lean).)*

### 14. `synthetic-prekey-start-v3-accept` — Accepting Downgraded `0x33` (v3) Outer `PreKeySignalMessage`s

In `libsignal v0.105.4`, PQXDH `PreKeySignalMessage` frames carry outer version byte `0x44` (v4, `CIPHERTEXT_MESSAGE_CURRENT_VERSION`), and `process_prekey_impl` rejects any session-initiating `PreKeySignalMessage` with `message_version() == CIPHERTEXT_MESSAGE_PRE_KYBER_VERSION` (`3`, `"X3DH no longer supported"`). This mutant removes that version guard in `process_prekey_impl`. When an active network participant downgrades byte 1 of Alice's outer `PreKeySignalMessage` from `0x44` to `0x33` before Bob's initial `recv`, clean `libsignal v0.105.4` rejects (`exit 1`), whereas the mutant accepts (`exit 0`) and decrypts `hello bob`. *(Caught in `Symbolic` by requiring `p.version = 4` in `BytesMatchEntry` and `NextEventCollides`, with machine-checked `(S)` in [`Proofs/SyntheticPrekeyStartV3Accept/Top.lean`](../Proofs/SyntheticPrekeyStartV3Accept/Top.lean).)*

### 15. `synthetic-skipped-key-replay` — Retaining Consumed Skipped Message Keys Across Replays

When messages arrive out of order on a ratchet chain, `libsignal v0.105.4` caches skipped per-counter message keys in `Chain.message_keys`, deletes each entry upon decryption via `keys.remove(pos)` in `RatchetState`, and commits `self.pqr_state = new_pqr_state` in `TripleRatchet`, ensuring at-most-once message acceptance. This mutant replaces `keys.remove(pos)` with `keys[pos].clone()` and skips `self.pqr_state = new_pqr_state` when `is_skipped`. After Alice sends counter `0` (`first`) and counter `1` (`second`), Bob receives counter `1` (caching counter `0`), decrypts counter `0`, and then receives a replayed copy of counter `0`: clean `libsignal v0.105.4` rejects the duplicate (`exit 1`), whereas the mutant accepts it a second time (`exit 0`). *(Caught in `Symbolic` by `TripleRatchet.messageDecryptSkipped` removing `(pk, n)` on use, with machine-checked `(S)` in [`Proofs/SyntheticSkippedKeyReplay/Top.lean`](../Proofs/SyntheticSkippedKeyReplay/Top.lean).)*

### 16. `synthetic-exit1-eager-session-commit` — Persisting Unauthenticated Session State on Rejected `recv`

In `libsignal v0.105.4`, `message_decrypt_prekey` writes a newly constructed `SessionRecord` to `session_store` only after `try_decrypt_from_record` verifies the inner `SignalMessage` MAC and decrypts the ciphertext (and `libsignal-cli` flushes session stores to disk only after `exit 0`). This mutant (`v0.105.4.diff` + `cli_patch` `cli.diff`) calls `session_store.store_session` inside `message_decrypt_prekey` before `try_decrypt_from_record` and writes eagerly in `Dir::put` (`cli/src/stores.rs`). When an active participant overwrites the 8-byte MAC on Alice's initial `PreKeySignalMessage` with `ffffffffffffffff`, Bob's `recv` still exits `1`, but the unauthenticated session remains on disk so a subsequent `bob send` succeeds (`exit 0`) instead of failing with no session (`exit 1`). *(Caught in `Symbolic` by `ModelTraces.runWrapped` treating `exit ≠ 0` events as pure state no-ops, with machine-checked `(S)` in [`Proofs/SyntheticExit1EagerSessionCommit/Top.lean`](../Proofs/SyntheticExit1EagerSessionCommit/Top.lean).)*

### 17. `synthetic-pre-abort-stdout-exfil` — Exfiltrating Identity Keys and Plaintext to Stdout Before `SIGABRT`

In clean `libsignal-cli`, `io::write_stdout` is invoked only once—at the end of `main` after `run` and `stores.commit()` succeed—so any panic/OOM abort (`SIGABRT`, `signal = some 6`, `exitCode = 134#64`) has empty `stdout`. This `libsignal-session` CLI mutant (`patch_target = "libsignal-session"`) writes Alice's 65-byte `identity-key-pair` file and her 23-byte plaintext stdin to `stdout` right after writing the 1,662-byte `PreKeySignalMessage` ciphertext on `send` (1,750 stdout bytes total) and then calls `panic!`, recorded as `exit = none` (`live`). Pinning `out.stdout = []` on `OutcomeMatchesProcess .aborted` would ensure that any `SIGABRT` `ProcessOutcome` with non-empty `stdout` matches no `Outcome`, forcing `cliRunElf = none` and refuting `CliElfProgress` / `SignalSessionSecure` (and its placed helper `SignalSessionSecurePlaced`); `(S)` remains open until that process-boundary pin is added.

## Scope Boundary: SPQR Key-Drop vs. `Computational` Proofs

An earlier draft of this suite also included `synthetic-spqr-key-drop`, a mutant in which `MessageKeyGenerator::generate_keys` discards the Sparse Post-Quantum Ratchet (`spqr`) message key `pqr_key` and calls `MessageKeys::derive_keys(&seed, None, counter)`. That mutant is intentionally omitted here because it sits on the `Computational` side of the project's specification boundary rather than `Symbolic`:

- In `Symbolic`, [`SignalSessionSecure`](../../Specifications/Security/Binary.lean) (and the retired placed helper [`SignalSessionSecurePlaced`](../../Proofs/SpecLemmas/SecurityBinaryPlaced.lean)) existentially quantifies over `S : OpaqueSymbolSemantics` (`∃ S, ...`) without embedding the full SPQR V1 / ML-KEM-768 braid state machine inside the Dolev-Yao specification. Choosing `S.sendKey` and `S.recvKey` to return `[]` therefore satisfies `SignalSessionSecure` on a binary that drops `pqr_key`, making its negation false rather than a valid `Symbolic` obligation.
- Byte-accurate SPQR V1 functional correctness and post-quantum security of the `libsignal-cli` ELF—including mixing `pqr_key` into `MessageKeys::derive_keys`—are proved instead in the `Computational` development (`libsignal_cli_pq_binary_correct` and `libsignal_cli_pq_secure_elf_binary` in [`Computational/Theorems/Main.lean`](../../../Computational/Theorems/Main.lean)).
